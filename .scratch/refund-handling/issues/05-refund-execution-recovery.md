# 审批后退款执行与失败恢复

Status: resolved

Blocked by: 04

Source: [refund-handling PRD](../PRD.md)

User stories: 6, 8, 27, 28

## What to build

交付审批通过后的资金执行生命周期。支付执行只能处理原始、已批准的退款申请，并使用稳定幂等标识完成执行中、执行成功或执行失败的状态迁移。执行失败保留履约冻结并重试原申请或转人工；执行成功将订单标记为已退款，但用户措辞只能说明已提交支付渠道，不能承诺银行到账。

## Acceptance criteria

- [x] 只有 `APPROVED_PENDING_EXECUTION` 的申请可以开始资金执行，并原子迁移到 `EXECUTING`。
- [x] 支付执行使用与原退款申请绑定的稳定幂等标识，重复消费或重试不会重复退款。
- [x] 支付渠道明确受理后状态进入 `EXECUTED`，订单进入已退款状态，并保留完整执行凭证。
- [x] 支付执行失败后状态进入 `EXECUTION_FAILED`，履约冻结保持不变且不会创建新退款申请。
- [x] 失败重试继续使用原申请、原审批和原幂等标识；无法安全重试时转人工。
- [x] 退款进度查询同时返回申请、审批和资金执行状态以及可安全展示的渠道信息。
- [x] Agent 将 `EXECUTED` 描述为已提交支付渠道处理，不声称银行账户已到账，也不承诺未获渠道保证的时效。
- [x] 状态迁移拒绝非法跳转，包括未审批直接执行、已拒绝执行和已执行再次执行。
- [x] 测试覆盖正常执行、重复执行、渠道超时后查询、明确失败、未知结果、失败重试和租约冲突。

## Comments

- 已新增受控的 `RefundPaymentGateway` 执行边界、`EXECUTING`/`EXECUTED`/`EXECUTION_FAILED` 状态、执行凭证和 V18 恢复字段。
- 未知结果恢复先查询渠道；渠道明确无记录时才用原退款申请和原幂等键重试，已受理则按旧状态对账，避免重复扣款。
