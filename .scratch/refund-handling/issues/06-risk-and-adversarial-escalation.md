# 高风险与恶意输入安全升级

Status: resolved

Blocked by: 02

Source: [refund-handling PRD](../PRD.md)

User stories: 13, 20, 21, 24, 36, 38, 39

## What to build

交付高风险、身份异常、规则未知及恶意输入场景的统一人工升级路径。Backend 输出风险等级和可追溯原因，Agent 只提升人工处理优先级，不自动退款。用户原因文本和外部数据始终视为不可信内容，不能修改 Tool 顺序、确认要求或安全策略；日志在保留审计关联能力的同时避免暴露原始敏感文本。

## Acceptance criteria

- [x] 高风险资格或提交结果始终返回人工处理语义，并创建或关联高优先级人工任务，不自动审批或执行退款。
- [x] 匿名、身份失效、订单归属不匹配、政策版本不兼容和无法判定资格均进入安全升级路径。
- [x] 原因文本中的角色伪造、Tool 指令、越权请求和提示注入不会改变既定调用顺序或安全门槛。
- [x] Agent 不因用户施压、情绪表达或声称已获授权而跳过身份校验、摘要展示、确认或人工审批。
- [x] 观测数据关联租户、用户、会话、订单、退款、审批、版本、规则 ID、确认、幂等、状态迁移、升级、重试和错误。
- [x] 日志不记录原始敏感退款原因；只使用原因码、脱敏摘要或受访问控制的引用。
- [x] 人工升级结果向用户提供准确的下一步和服务状态，不泄露内部风险规则或其他用户数据。
- [x] 安全评测已覆盖越权、匿名、提示注入、高风险、未知结果和敏感日志六类场景；安全样例通过定向回归，发布门禁要求关键场景三次全通过。
- [x] 任一越权操作、确认绕过、Agent 指定金额、自动高风险退款或敏感日志泄露都会使测试失败。
