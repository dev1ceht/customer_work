# 退款资格咨询安全链路

Status: resolved

Blocked by: None

Source: [refund-handling PRD](../PRD.md)

User stories: 1, 2, 10, 11, 12, 15, 17, 29, 30, 35

## What to build

交付一个只读、可独立演示的退款资格咨询链路：客户询问退款时，Agent 能读取明确分离的支付状态和履约状态，由 Backend 根据版本化退款政策计算资格与全部可退余额，再通过结构化 Tool 结果解释可申请、需人工处理或不可申请。未支付、已发货、部分退款及其他售后意图必须进入正确分支，咨询本身不能创建退款申请。

本切片同时建立第一版标准生产 Skill 包：能力说明、退款政策参考、订单状态规则和 Tool 契约。规则参考必须可追溯，Backend 的 Mock 与 MyBatis 适配器必须表现一致。

## Acceptance criteria

- [x] 订单查询结果分别表达支付状态和履约状态，不再要求 Agent 从单一混合状态推断退款资格。
- [x] 资格检查只接受订单标识；时间窗口、资格结论和退款金额均由 Backend 计算。
- [x] 资格结果结构化返回 `ELIGIBLE`、`HUMAN_REVIEW` 或 `INELIGIBLE`，并包含原因码、全部可退余额、风险等级、政策版本和规则 ID。
- [x] 已支付且未发货的有效订单可以完成只读资格咨询，且不会产生退款、审批或履约冻结记录。
- [x] 未支付订单被引导到取消订单流程；已发货订单被引导到退货退款或人工流程；部分退款明确转人工。
- [x] Mock 与 MyBatis Backend 通过同一组资格契约测试，并对相同输入给出相同业务语义。
- [x] Agent 行为测试证明先查询订单再检查资格，并能区分“咨询”与“提交申请”的用户意图。
- [x] 生产 Skill 包只包含能力说明和三类参考文档，不新增承担安全校验职责的脚本，也不引入运行时尚未支持的清单格式。
- [x] 退款政策参考包含稳定规则 ID、来源、负责人、生效日期和政策版本，并与 Backend 返回证据一致。
- [x] 现有相关测试迁移到结构化契约后全部通过，并新增未支付、已发货和部分退款边界用例。

## Answer

已交付退款资格咨询安全链路：订单事实和退款资格均改为结构化只读契约，政策判断集中在 Backend，
Mock/MyBatis 语义对齐；生产 Skill 包补齐退款政策、订单状态和 Tool 契约三类可追溯参考。
咨询不会调用写工具；实际申请、部分退款、已发货及已有生效退款统一转人工。

最终整合回归共 54 个测试，0 失败；其中 16 个依赖 MySQL 的集成测试按项目约定跳过。
另外补充 5 个与生产 Skill 分离的独立 YAML eval 用例；当前 Windows 环境不支持 `skill-up` CLI，
因此已由 Maven 结构测试校验，并提供 Linux 临时组装与运行脚本供 CI 执行真实模型评测。
