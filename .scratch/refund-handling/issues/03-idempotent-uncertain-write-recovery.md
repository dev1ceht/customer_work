# 重复提交与写入不确定性恢复

Status: resolved

Blocked by: 02

Source: [refund-handling PRD](../PRD.md)

User stories: 7, 18, 19

## What to build

交付重复申请与网络不确定状态下的安全恢复路径。相同订单的重复提交必须返回原退款申请；写操作超时后，Agent 和 Tool 先按稳定幂等标识查询实际结果，只在明确不存在时使用同一标识重试一次。无法确认结果时转人工，绝不猜测申请已受理。

## Acceptance criteria

- [x] 待审核、审批后待执行、执行中和执行完成的既有申请均返回 `EXISTING` 及原退款单号，不创建新申请。
- [x] 并发提交在数据库约束和 Backend 逻辑共同保护下只产生一套退款、审批和履约冻结记录。
- [x] 写 Tool 使用稳定、可追踪的幂等标识，并能按该标识或业务唯一键查询已有结果。
- [x] 写操作超时后先查询结果；只有结果明确不存在时才允许以同一幂等标识重试一次。
- [x] 查询仍无法判断是否成功时返回未知语义并立即转人工，不继续自动写入。
- [x] Agent 仅在获得明确退款单号或 `EXISTING` 结果时告知用户申请已受理。
- [x] 只读 Tool 的瞬时失败最多自动重试一次，并保留原始追踪上下文。
- [x] 测试覆盖串行重复、并发重复、提交已成功但响应丢失、明确未写入后重试以及持续未知五类场景。
- [x] 所有测试证明不会重复创建退款、审批记录、履约冻结或资金执行任务。
