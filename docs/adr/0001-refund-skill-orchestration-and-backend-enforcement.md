# 退款 Skill 负责编排，Backend 强制安全

`refund-handling` 只负责识别意图、组织对话、安排工具顺序和生成用户口径；可信身份、订单归属、退款资格、可退金额、幂等、履约冻结、人工审批和资金执行必须由 Backend 强制执行。选择这一分层，是因为把硬规则只写在 Skill 或脚本中虽然迭代更快，却会让模型误判、漏调工具或运行时未加载脚本时绕过资金安全；反过来把全部对话流程写进 Backend 又会失去 Skill 的业务可读性和可演进性。

## Consequences

- Skill 可以更新触发与回复流程，但不能放宽 Backend 的安全约束。
- Backend 在提交退款时必须重新校验，不能信任 Agent 传入的资格、金额、用户身份或订单状态。
- 退款政策以版本化快照留在 Skill 包中，Backend 返回相同的政策版本和规则编号，测试负责校验两者一致。
- Skill 脚本不承担资金校验；首期不启用脚本执行。
